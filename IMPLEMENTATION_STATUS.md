## Backend v3 implementation — 17 October 2026

Work continues in the existing public `abitiyoso/daylio` repository on `codex/backend-v3-workflows`; the original authenticated API, PostgreSQL service, migrations and marketing are retained. Approved UX source is preserved as non-runtime `design-reference/`. Audit and route/state maps: `docs/DAYLIO_V3_GAP_ANALYSIS.md`, `docs/DAYLIO_V3_WORKFLOW_MAP.md`, `docs/BACKEND_V3_API.md`.

**Phase 1 P0 is locally implemented and exercised end-to-end.** The new four-role shell, present-child batch logging with exceptions and grouped publication, morning handover, linked-child Today/Story, exception/closing workflow and two pickup journeys use actual authenticated HTTP routes and persisted records. **Phase 2 P1 core journeys are also locally implemented and exercised:** approved passport versions, age/rubric observations and human-signed reports/private PDF, CRM qualification and manual WhatsApp drafts, capacity/price-confirmed enrollment, owner metrics and role-scoped deterministic LEO. This is an MVP verification boundary, not a claim that every advanced matrix detail or production rollout is complete.

Evidence: `tests/v3-workflows.test.mjs` adds **13** cross-role PostgreSQL tests; total **36 passed** in `evidence/v3-automated-tests.txt`. `evidence/v3-browser-results.json` records P0 UI journeys and twelve role/device captures at 1440/820/390px; `evidence/v3-business-browser-results.json` records P1 UI journeys. Earlier marketing/private-media regression was rerun in `evidence/browser-results.json`. All browser identities/children are explicitly synthetic and isolated from production; the database/RLS, APIs, persistence, image processing and report export are real. Migration 011 is applied after the original ten; no existing business records are replaced. No external messages or provider transactions were sent.

Remaining scope: cursor pagination beyond the 1,500-record workspace window, historical state reconstruction, richer calendar and followup assignment UX, partial-day place allocation, portfolio/report PDF polish and non-Latin font support, full assistive-technology UAT, and hosted operational/provider validation. Group media fails closed when a viewer cannot verify all declared depicted-child consents; broader group-photo sharing needs a dedicated reviewed policy. P2 billing/commercial milestones remain documented. **F27–F29 and F42 live video/provider integration are DEFERRED, explicitly outside this phase.**

## Baseline and decisions

### Landing-to-workspace recheck

Desktop **Masuk** and the application preview already linked to `/workspace`. Recheck found the mobile header hides desktop actions but its menu lacked a login link. The landing SSR now adds **Masuk** to the mobile menu without changing the v4 source, stylesheet, imagery or logo. `scripts/browser-entry-test.mjs` passed for all four roles: public landing → desktop/mobile login entry → real authenticated role dashboard → `/api/v1/workspace/context` with persisted authorized children. Anonymous API returns 401; returning through the public application preview with an active session retains the authenticated role. Evidence: `evidence/entry-browser-results.json` and `evidence/screenshots/entry/`. This verifies the local application, not a hosted production deployment.

The supplied ZIP had static HTML/CSS/JS, local sample metrics/scripted LEO/still-image CCTV and no backend or existing Elenio source. This implementation adds Next.js/TypeScript, PostgreSQL RLS, Supabase Auth boundaries, real API-backed workspace workflows, private media and automated tests. v4 source/layout/assets are retained. Local sandbox fixtures are explicit and production-disabled. The API adapts the proposed endpoint names; the generated OpenAPI inventory documents actual paths. Domain workflow records share a constrained JSONB table with tenant and child foreign keys, rather than adding a physical table for each suggested name.

Evidence: `tests/contracts.test.mjs`, `tests/workflows.test.mjs`, `tests/reliability.test.mjs`, `evidence/automated-tests.txt`, `evidence/browser-results.json`, and `evidence/screenshots/`. Browser identity is a synthetic local fixture, not real Supabase verification. The embedded PostgreSQL tests execute migrations/RLS; they are not a hosted disaster recovery drill. A missing evidence file means that check has not yet completed, never an implicit pass.
